## Backup Safety

- [x] Folder and registry backups use unique staging output and promote only after completion.
- [x] Retention pruning happens only after the new snapshot and checkpoint are finalized.
- [x] Failure/cancellation leaves prior valid snapshots intact and cleans only owned staging data.
- [x] Source/destination containment, drive-root mistakes, traversal, and reparse points are rejected.
- [x] A strict copy plan prevents inaccessible files from being silently omitted.
- [x] Destination free space is checked with an overflow-safe margin before copying.
- [x] Structured operation results carry status, run ID, files, bytes, warnings, errors, and output path.
- [x] Retention is owner-aware so sanitized display-name collisions cannot prune another game's run.
- [x] Tests cover locked files, cancellation, retention 1/2/3, path relationships, casing, and failed promotion.

## Auto-Backup And Shared State

- [x] File events are debounced per game and transient sharing failures use bounded retry/backoff.
- [x] Cooldown starts only after a completed backup.
- [x] Live watchers are capped; overflow entries retain poll-based monitoring.
- [x] Catalog, settings, checkpoints, history, backup, restore, and compression coordinate across processes.
- [x] Backup and compression share one root operation lease and cannot mutate the same root concurrently.
- [x] JSON writes use unique temporary files, flush-to-disk, replace, and `.bak` recovery.
- [x] Catalog/settings reload before mutation to preserve changes from another GSBT process.
- [x] Timers, watchers, HTTP responses, registry handles, chart subscriptions, and controllers have explicit disposal.
- [~] Extended watcher/window resource soak remains a clean-machine/manual release check.

## Integrity And Restore

- [x] Offline removable/network destinations no longer erase remembered `last_backup` history.
- [x] Schema-2 checkpoints record run identity, source, writer version, inventory, size, and SHA-256 hashes.
- [x] Fast verification checks inventory/size; full verification checks SHA-256 content.
- [x] `gsbt verify` supports human, JSON, and AI progress output.
- [x] GUI context menu exposes **Verify latest backup** with a clear result and timestamp status.
- [x] Registry exports require a valid header and restore only to their checkpointed subtree.
- [x] Core, CLI, and GUI share one restore planner/result model.
- [x] Restore supports Replace, Merge, and alternate-folder modes.
- [x] Restore previews and fully verifies before confirmation; AI mutation requires `--yes`.
- [x] Folder restore stages, journals, swaps, SHA-256 verifies, and rolls back on failure/cancellation.
- [x] Registry restore creates a safety export and rolls back a failed import.
- [x] Restore has distinct automation exits for unsafe target, space, verification, rollback, and partial outcomes.
- [x] Tests cover dry run behavior, alternate/merge/replace results, modified snapshots, and safety copies.
- [D] Direct `.7z` restore is deferred until archives carry a trusted per-game snapshot index. Multi-game archives are never extracted over live saves.
